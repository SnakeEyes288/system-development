# คู่มือใช้ Skill สำหรับงาน UI

ใช้คู่มือนี้เมื่อสร้างหรือแก้ UI ที่ผู้ใช้มองเห็นหรือโต้ตอบได้ รวมถึงข้อความ สี และระยะห่าง ใช้ในขั้น 3.0 เมื่อทำ prototype และขั้น 4.0 เมื่อแก้ UI จริง ให้ใช้รายละเอียดตามขอบเขตของงาน

## ค้นหา Skill ก่อนเริ่ม

1. ตรวจ Skill ที่ Agent เปิดใช้ได้ ถ้าต้องอ่านไฟล์เอง ให้ค้นที่โฟลเดอร์ Skill ของโปรเจกต์และของ Agent เช่น `.agents/skills/`, `.codex/skills/` หรือ `.claude/skills/` ตามระบบที่ใช้งาน
2. ใช้ `SKILL.md` ของ `frontend-design` ที่พบ สำหรับ `ui-ux-pro-max` ให้ตรวจด้วยว่าโฟลเดอร์เดียวกันมี `scripts/search.py` และ `data/` แล้วใช้พาธของสคริปต์จากตำแหน่งจริง
3. ถ้าขาดตัวใด ให้ใช้คำสั่งด้านล่างเฉพาะตัวที่ขาด เมื่อขอบเขตงานอนุญาตให้ติดตั้งแล้ว ตรวจไฟล์อีกครั้งหลังติดตั้ง ถ้า Agent แสดงรายการ Skill เดิม ให้อ่านไฟล์จากพาธที่ยืนยันได้หรือเปิดเซสชันใหม่ตามวิธีของ Agent

### ติดตั้งในโปรเจกต์สำหรับ Codex

รันจาก root ของโปรเจกต์ โดยใช้ Node.js 22.20 ขึ้นไปสำหรับชุดคำสั่งนี้ บน Windows PowerShell ใช้ `npx.cmd` ได้หากเรียก `npx.ps1` ไม่ได้ หลังติดตั้งให้ตรวจ `.agents/skills/<ชื่อ Skill>/SKILL.md` ในโปรเจกต์

```shell
npx --yes skills add Ilm-Alan/frontend-design --skill frontend-design --agent codex --yes
npx --yes ui-ux-pro-max-cli init --ai codex
```

เลือก `frontend-design` ของ Ilm-Alan เพราะเป็นฉบับ Eight Aesthetic Anchors ที่กระบวนการนี้อ้างถึง ผู้ดูแล repo มีคำสั่ง Git clone สำหรับ Codex, Claude Code และ Gemini CLI ด้วย สำหรับ Agent อื่นให้ใช้ชื่อ Agent ที่เครื่องมือติดตั้งรองรับและตรวจตำแหน่งที่คำสั่งรายงาน [frontend-design](https://github.com/Ilm-Alan/frontend-design#install) · [UI/UX Pro Max](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill#installation) · [Skills CLI](https://github.com/vercel-labs/skills#install-a-skill)

คำสั่งติดตั้งใช้เครือข่าย ส่วนการค้น `ui-ux-pro-max` ใช้ Python 3 และข้อมูลบนเครื่อง หากมี Python Launcher บน Windows ให้ใช้ `py -3` เป็นตัวรันได้ [ข้อกำหนดของ UI/UX Pro Max](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill#prerequisites)

## ใช้ทั้งสองแนวทางกับ UI ที่จะเปลี่ยน

1. **ทิศทางภาพจาก `frontend-design`** เปิด Skill แล้วดูทิศทางภาพของโปรเจกต์ก่อน สำหรับฟีเจอร์ใหม่ให้ระบุงานหลักของผู้ใช้และเลือก anchor ที่สอดคล้องกับแบรนด์ สำหรับ UI เดิมให้ใช้ token, component และลำดับชั้นภาพของระบบเดิม ตรวจว่าการเปลี่ยนข้อความหรือ spacing ยังสอดคล้องกับหน้าจอที่ใช้รูปแบบเดียวกัน
2. **คำแนะนำจาก `ui-ux-pro-max`** เปิด Skill และรัน `scripts/search.py` ด้วยปัญหาที่กำลังแก้ ใช้ `--design-system` เมื่อกำหนดทิศทาง UI ใหม่ และใช้ `--domain ux` หรือ `--stack` ตามคำแนะนำของ Skill เมื่อเป็นปัญหาเฉพาะจุด ค้นโดยใช้คำอธิบายทั่วไปที่เพียงพอกับโจทย์
3. **ตรวจความเกี่ยวข้องของผลค้นหา** เทียบตัวเลือกกับผู้ใช้ ประเภทหน้าจอ ระบบดีไซน์เดิม และข้อกำหนดโปรเจกต์ ถ้าผลว่างหรือหลุดโจทย์ ให้ลองคำค้นที่เจาะจงขึ้นหนึ่งครั้ง เลือกใช้ข้อที่ตรงกับงานและระบุเหตุผลเมื่อเสนอทางเลือกอื่น
4. **ใช้กับโค้ดและตรวจหน้าจอจริง** นำข้อที่เลือกไปใช้กับ component, token, copy หรือ interaction ที่เปลี่ยน ตรวจเส้นทางที่ผู้ใช้ทำจริง ในขั้น 4.0 ให้นำสิ่งที่ตกลงในขั้น 3.0 ไปใช้กับ UI จริงและค้นเพิ่มเมื่อเจอปัญหาที่ต้นแบบยังตอบไม่ได้ Agent หลักรับผิดชอบตรวจผลทั้งหมด แม้มีการแบ่งงานตามเครื่องมือและสิทธิ์ของสภาพแวดล้อม

ตัวอย่างคำค้นหาสำหรับปัญหา focus ของ dialog ให้แทน `SKILL_DIR` ด้วยพาธจริงของ `ui-ux-pro-max`

```shell
python3 "SKILL_DIR/scripts/search.py" "keyboard focus modal" --domain ux
```

```powershell
py -3 "SKILL_DIR/scripts/search.py" "keyboard focus modal" --domain ux
```

## แนวทางที่ใช้ได้เมื่อแหล่งใดแหล่งหนึ่งไม่พร้อม

ใช้ Skill ที่พร้อมร่วมกับหลักด้านล่างสำหรับส่วนที่ขาด ใช้กรณีเครื่องออฟไลน์ หาไฟล์ไม่พบ ใช้ตัวรันไม่ได้ หรือคำค้นที่ปรับแล้วไม่ให้ผลที่ตรงโจทย์ เก็บการเปลี่ยนแปลงให้สอดคล้องกับขอบเขตงาน

- **ภาพและเนื้อหา** ให้การจัดวางและตัวอักษรสะท้อนลำดับงานหลักของผู้ใช้ ใช้สีเด่นอย่างมีหน้าที่ รักษา token และคอมโพเนนต์ร่วม ใช้ข้อความที่สื่อการกระทำหรือสถานะได้ชัดเจน
- **การใช้งาน** ตรวจสถานะที่ได้รับผล เช่น ว่าง กำลังโหลด ผิดพลาด หรือสำเร็จ ใช้ชื่อที่เทคโนโลยีช่วยเข้าถึงอ่านได้ ตรวจ focus การใช้งานด้วยคีย์บอร์ด ความต่างสี และการตัดบรรทัดบนหน้าจอขนาดที่รองรับตามลักษณะของงาน

## บันทึกสิ่งที่ใช้จริง

บันทึกใน `.pipeline/DESIGN_SYSTEM.md` ตามภาษาเอกสารโครงการ งานเล็กใช้สรุปสั้น ๆ ต่อการเปลี่ยนแปลง ส่วนงานใหญ่ใช้หัวข้อแหล่งอ้างอิงและผลตรวจในเอกสารดีไซน์

| ส่วนที่เปลี่ยน | หลักจาก frontend-design | หลักจาก ui-ux-pro-max | จุดที่นำไปใช้และผลตรวจ |
| --- | --- | --- | --- |
| ปุ่มยืนยันใน dialog | อ่าน Skill และใช้ลำดับชั้นปุ่มเดิม | ค้น `keyboard focus modal` และเลือกแนวทางแสดง focus ให้เห็นชัด | ใช้ปุ่มชุดเดิมและตรวจเห็น focus ring เมื่อกด Tab |

เมื่อใช้แนวทางในตัว ให้ระบุเหตุผลและแหล่งที่ใช้จริง เช่น `ui-ux-pro-max: แนวทางในตัว เพราะค้นหาไฟล์ Skill ไม่พบ` บันทึกผลตรวจเฉพาะสิ่งที่ตรวจแล้ว
